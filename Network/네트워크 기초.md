# 네트워크 용어 정의
## internet 
> [!NOTE] internetworking?
> **인터네트워킹**(internetworking)은 여러 [컴퓨터 망](https://ko.wikipedia.org/wiki/컴퓨터_망)을 상호연결 하는 실무를 의미한다.  일반적으로 이는 연결된 네트워크에 있는 어떠한 [호스트](https://ko.wikipedia.org/wiki/%ED%98%B8%EC%8A%A4%ED%8A%B8_\(%EB%84%A4%ED%8A%B8%EC%9B%8C%ED%81%AC\) "호스트 (네트워크)") 쌍이라도 하드웨어 수준의 네트워킹 기술에 관계없이 메시지를 교환할 수 있게 한다. 이렇게 상호 연결된 네트워크 시스템을 인터네트워크(internetwork) 또는 간단히 인터넷(internet)이라 부른다.
> [출처 : wikipedia](https://ko.wikipedia.org/wiki/인터네트워킹)

연결되는 네트워크의 수가 증가할수록 복잡도가 증가함에 따라 적절히 연결하여 중개할 수 있는 인터네트워킹(*라우터*)가 필요함

## Internet
TCP/IP 기반 네트워크로 우리가 사용하는 인터넷을 지칭함

## 인터페이스(Interface)
시스템과 전송 매체의 연결 지점에 대한 규칙

## 프로토콜(protocol)
시스템이 데이터를 교환할 때 사용하는 소프트웨어적 규칙

## 시스템(system)
내부 규칙에 따라 자율적으로 동작하는 대상
물리적 : 컴퓨터, 자동차 ..
논리적 : 운영체제, 프로세스 ..



# 시스템의 구분
## 노드(node)
컴퓨터 이론 분야에서 특정 시스템을 가르키는 일반적인 용어로 데이터를 주고 받을 수 있는 모든 시스템을 노드라 한다.

## 호스트(host)
컴퓨팅 기능이 있는 시스템으로 인터넷 바깥쪽에서 일반 사용자의 창구 역할을 한다.

> [!NOTE] 노트, 호스트 차이
> 호스트는 컴퓨팅 기능을 수행할 수 있다. 여기서 컴퓨팅 기능이란 우리가 일반적으로 앱을 설치하고 실행하는 것을 말한다.


## 라우터(router)
인터넷 내부를 구성하며, 기본으로 데이터 전송 기능을 포함한다. 
네트워크를 통해 데이터를 전송할 때 경로를 설정함

## OSI 7계층 모델

![OIS7](https://www.guru99.com/images/1/102219_1135_TCPIPvsOSIM1.png)
> [OSI 7 Layer Model](https://www.guru99.com/difference-tcp-ip-vs-osi-model.html)

1. 물리 계층 : 호스트를 전송 매체와 연결하기 위한 인터페이스와 전송 매체 특성을 다룸
2. 데이터 링크 계층 : 물리 계층의 오류를 해결
   오류 제어(error control) : 전류 오류 감지 -> 재전송
   흐름 제어(flow control) : 
3. 네트워크 계층 : 주소(adress), 호스트와 호스트 사이의 올바른 전송 경로 선택(혼잡 제어 포함) -> 라우터의 기능
4. 전송 계층 : 송수신 프로세스 사이의 논리적 연결(end-to-end) 지원. 안전한 데이터 전송
   TCP/IP, UDP 가 이 계층에 포함되며 TCP 에서 종단간의 흐름제어, 오류제어를 지원함
5. 세션 계층 : 대화(dialog) 개념을 지원하는 상위의 연결 지원
   동기화(synchronization) :
6. 표현 계층 : 데이터의 표현 방법, 압축(compression), 암호화(Encryption/Decryption)
7. 응용 계층 : 우리가 사용하는 일반적인 앱 등.

# 인터네트워킹
네트워크와 네트워크의 연결, 연결되는 네트워크의 수가 증가할수록 복잡도가 커짐 -> 적절히 연결하여 중계할 수 있는 인터네트워킹(라우터)가 필요

물리적 연결 뿐만 아니라 논리적 연결, 호환성 필요(데이터의 경로 설정 기능 수행)

## 네트워크의 연결
인터네트워킹 시스템의 주요 기능은 전송 데이터의 경로 선택과 관계가 있다. 예를 들어 네트워크1, 2, 3에서 네트워크1의 데이터를 네트워크3의 누구에게 보낼 것인지 선택해야한다.

이 기능은 7계층 모델에서 네트워크 계층을 포함한 하위 3개의 계층(물리, 데이터 링크, 네트워크 계층)에서 수행한다.

인터네트워킹 시스템에 연결된 네트워크들은 물리적으로 같은 종류일 필요가 없으며, 상위 계층 프로토콜이 지원하는 논리적 기능도 다를 수 있다. 하지만 연결된 모든 네트워크에 대해 물리적이고 논리적인 인터페이스를 모두 지원해야한다. 즉, 네트워크1, 2, 3과 개별적으로 연동할 수 있어야 한다. 또한 이 과정에서 데이터 표현 방식을 포함하여 양쪽 네트워크의 프로토콜이 서로 일치하지 않으면 변환하는 작업을 수행해야한다.

## 데이터 단위
![데이터단위](https://networkwalks.com/wp-content/uploads/2020/10/NW-OSI-Model-5.png)
> [출처]([https://networkwalks.com/wp-content/uploads/2020/10/NW-OSI-Model-5.png](https://networkwalks.com/osi-model/))

네트워크 프로토콜을 사용해 데이터를 교환할 때, 먼저 데이터를 특정 형태로 규격화하는 작업이 필요하다. 예를 들어, 우편물을 보낼 때 정해진 규격 봉투를 사용하는 것과 같다.

네트워크에서는 데이터를 프로토콜에서 정의된 데이터 규격에 맞게 묶어주어야 하고 이와 같은 한 단위의 규격으로 묶인 전송 데이터를 데이터 단위라 한다.

OSI 7계층 모델의 각 계층에서 규격화된 데이터는 아래 그림과 같이 고유 명칭이 있고 계층에 상관없이 사용할 때는 통칭하여 PDU(Protocol Data Unit)이라 부른다.

> [!NOTE] Segment, Packet, Frame
> - TPDU(Transport Protocol Data Unit), 전송계층에서 사용하는 단위로 TCP 프로토콜에서는 세그먼트(Segment)라 부르고 UDP에서는 데이터그램(Datagram)이라 부른다. 일반적인 상황에서 데이터그램은 계층 4 프로토콜의 전송 데이터를 가리킨다.
> - NPDU(Network Protocol Data Unit), 네트워크 계층에서 사용하며 보통 패킷(Packet)이라 부른다. 패킷은 원래 네트워크 계층의 IP 프로토콜에서 유래했지만 요즘은 네트워크 계층의 전송 데이터를 의미한다.
> - DPDU(Data Link Protocol Data Unit), 데이터 링크 계층에서 사용하며, 보통 프레임(Frame)이라 부른다.



## 게이트웨이(Gateway)
![게이트웨이](http://www.ktword.co.kr/img_data/4842_1.JPG)
> [출처](http://www.ktword.co.kr/test/view/view.php?no=4842)

인터네트워킹 시스템은 용어 자체로 의미를 설명하기 위한 개념적 명칭이고 인터네트워킹 기능을 수행하는 시스템을 일반적으로 게이트웨이(Gateway)라 부른다.

게이트웨이는 일반적으로 지원하는 기능에 따라 리피터, 브리지, 라우터 등으로 나뉜다.

![인터네트워킹](../img/Pasted%20image%2020260928124420.png)
### 리피터(Repeater)
리피터는 물리 계층의 기능을 지원한다.
물리신호는 거리가 멀수록 감쇄되기 떄문에 리피터가 신호를 증폭하여 중계 기능을 수행한다.

### 브리지(Bridge)
리피터는 단순 신호를 증폭하는 역할을 하며, 전송 과정에서 발생하는 노이즈나 물리적 오류를 다루지 않는다. 이 기능을 수행하는 브리지(Bridge)는 리피터 기능에 데이터 링크 계층의 기능이 추가된 것으로 물리 계층에서 발생한 오류를 해결해준다.
예) 가정용 무선 공유기

논리적으로 분리된 세그먼트(Segment) 사이에서 같은 프로토콜을 이용하는 경우, 동일 세그먼트인지 구분하여 처리하고 서로 다른 프로토콜을 사용하는 경우 프로토콜 변환 기능 제공
### 라우터(Router)
라우터(Router)는 물리 계층, 데이터 링크 계층, 네트워크 계층의 기능을 지원한다.

네트워크 계층은 경로 선택 기능을 지원해야 하므로 임의의 네트워크에서 들어온 데이터를 주변 라우터의 정보를 저장한 라우팅 테이블을 사용해 어느 네트워크로 전달할지 판단한다.

# 프로토콜
프로토콜(Protocol)은 통신 시스템이 데이터를 교환하기 위한 통신 규칙으로 OSI 7 Layer 모델에서는 각 계층에서 수행하는 프로토콜이 서로 역할을 분담하여 독립적으로 동작한다. 따라서 1 계층은 1 계층 끼리, 2 계층은 2 계층 끼리 통신할 수 있는 프로토콜이 존재한다.

> [!NOTE] SDU(Service Data Unit)
>

# 주소의 표현
시스템을 설계할 때 기능이나 목적과 함께 고유한 구분자(Identifier)를 부여하는 방법도 고려해야한다.

대상을 유일하게 구별하는 구분자는 일반적으로 다음의 네 가지 특징이 있다.
- 유일성 : 서로 다른 대상이 같은 구분자를 갖지 않는 유일성을 보장해야한다. 그러나 이론적으로 완전한 확장성을 전제로하는 유일성은 보장 불가하다.
- 확장성 : 시간이 흐르며 증가하는 시스템의 규모에 맞게 구분자의 양이 증가하여야 하므로 합리적인 기준으로 확장의 정도를 예측하여야 한다.
- 편리성 : 숫자 주소보단 사용자가 이해하기 쉬운 문자 이름으로 매핑할 수 있어야한다.
- 정보의 함축 : 적절한 부가 정보들이 함축되어야한다. 예) 집주소, 주민번호 등

## 주소와 이름
시스템을 지칭하는 구분자는 내부에서 처리되는 숫자 기반의 주소(Address)와 함께 편의성을 위한 문자 이름(Name)을 제공해야한다. 
예) IP주소, MAC 주소, TCP의 포트 주소 등

### IP 주소
네트워크 계층의 기능을 수행하는 IP 프로토콜이 호스트를 구분하기 위해 사용하는 주소 체계로 32비트의 이진 숫자로 구성되고 보통 8비트씩 네 부분으로 나누어 십진수로 표현한다.

![IP주소](https://blog.kakaocdn.net/dna/lUYbw/btsGcKPh2Zg/AAAAAAAAAAAAAAAAAAAAAB92SnaADof1PKvXuqFcp_08jA9EkcfvSQysxTxMqz-G/img.png?credential=yqXZFxpELC7KVnFOS48ylbz2pIh7yKj8&expires=1790780399&allow_ip=&allow_referer=&signature=Ty1R0fuvOvDX8h4GZkDalvSWQAM%3D)
> [IPv4 주소](https://zigispace.net/1254)

이와 같이 숫자로 된 주소조차 외우기 어려우므로 문자로 된 www.korea.co.kr 등의 도메인 이름을 사용한다.

최근 IPv4의 주소 체계는 시스템의 규모 증가로 인해 더 이상 새로운 구분자의 생성이 불가해졌다. 그래서 도입한 새로운 주소 체계가 IPv6로 128bit 주소 체계이다.

IP 주소는 임의로 할당되는 것이 아니라, 특정 규칙에 따라 인접한 주소들을 그룹으로 묶어 관리한다.

### 호스트 이름
인터넷에서 특정 호스트와 연결하려면 해당 호스트의 IP 주소를 알아야 하고, 인터넷 내부의 네트워크 계층은 호스트 IP를 주소로 구분한다. 하지만 사용자는 숫자로 된 IP 주소를 기억하기 어렵기 때문에 문자로 된 호스트 이름을 사용한다.

사용자가 문자로 된 호스트의 이름을 주소창에 작성하면 DNS 서버의 이름을 IP 주소로 변환해주는 기능을 사용해 IP 주소를 얻는다.
